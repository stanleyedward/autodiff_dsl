# Extension results: test programs and generated code

Each section shows the input program, the test that checks it (in [extras/testext.py](../extras/testext.py)), and the generated code with the extension off and on. All other extensions are off in both. The code is trimmed from the compiler's output (`...` marks skipped lines); the full output is in [before_after.md](before_after.md), regenerated by `python extras/show_before_after.py`.

## Remove atomics on thread-exclusive arrays

In a `@simd` reverse pass every adjoint update is an `atomic_add`. An array that is only accessed at the thread's own index (`x[thread_id()]`) can't be shared, so its atomic is dropped.

[extras/loma_code/scale.py](../extras/loma_code/scale.py):

```python
@simd
def scale(x : In[Array[float]], y : In[float], z : Out[Array[float]]):
    i : int = thread_id()
    z[i] = x[i] * y

rev_scale = rev_diff(scale)
```

`test_exclusive_arrays_c`:

```python
assert 'atomic_add((_dx' not in ir      # x only read as x[i]: atomic removed
assert 'atomic_add(_dy' in ir           # y read by every thread: atomic kept
```

Generated `rev_scale`:

```diff
 	i : int = thread_id()
 	...
-	atomic_add((_dx_2yW4Ac)[i],((z)[i]) * (y))
+	(_dx_2yW4Ac)[i] = ((_dx_2yW4Ac)[i]) + (((z)[i]) * (y))
 	atomic_add(_dy_q9GFz6,((z)[i]) * ((x)[i]))
```

## TBR analysis

The reverse pass pushes every overwritten variable onto a stack. `s` in `s = s + x[i] * w` is never read when computing derivatives, so its old values aren't saved. `i` is an index and still is.

[extras/loma_code/sum_loop.py](../extras/loma_code/sum_loop.py):

```python
def sum_loop(x : In[Array[float]], n : In[int], w : In[float]) -> float:
    i : int = 0
    s : float = 0.0
    while (i < n, max_iter := 1000):
        s = s + x[i] * w
        i = i + 1
    return s

d_sum_loop = rev_diff(sum_loop)
```

`test_tbr_sum_loop`:

```python
assert results[False][0] == 2000       # s and i pushed, 1000 iterations each
assert results[True][0] == 1000        # only i
assert results[False][1] == results[True][1]   # same dx
```

Generated `d_sum_loop`:

```diff
-	_t_float : Array[float, 1000]
-	_stack_ptr_float : int = (int)(0)
 	_t_int : Array[int, 1000]
 	...
 	while (i) < (n) :
-		(_t_float)[_stack_ptr_float] = s
-		_stack_ptr_float = (_stack_ptr_float) + ((int)(1))
 		s = (s) + (((x)[i]) * (w))
 		(_t_int)[_stack_ptr_int] = i
 	...
```

## Checkpointing

`checkpoint := k` moves the loop body into a segment function that runs k iterations. The outer loop saves only the state at segment boundaries, and the reverse pass recomputes one segment at a time.

[extras/loma_code/ckpt_auto.py](../extras/loma_code/ckpt_auto.py):

```python
def f(x0 : In[float], n : In[int]) -> float:
    i : int = 0
    x : float = x0
    y : float
    z : float
    while (i < n, max_iter := 100, checkpoint := 10):
        y = sin(x) * 0.5
        z = y * y
        x = x + z * 0.1
        i = i + 1
    return x

d_f = rev_diff(f)
```

`test_checkpoint_auto` (C) and `test_checkpoint_slang` (GPU, [kernel_ckpt.py](../extras/loma_code/kernel_ckpt.py)):

```python
assert results['ckpt_plain'][1] == results['ckpt_auto'][1]   # identical gradients
assert results['ckpt_plain'][0] == 500                       # 5 values x 100 iterations
assert results['ckpt_auto'][0] == 80                         # d_f + one segment's reverse
...
np.testing.assert_allclose(results['kernel_ckpt'], results['kernel_plain'], rtol=1e-6)
```

`test_checkpoint_two_float_states` covers loops with two float states (see [Bug 1 in the guide](../loma_extensions_guide%281%29.md#bug-1-the-reverse-pass-restored-a-calls-outputs-in-the-wrong-order)).

Forward loop of `d_f`, before (everything pushed every iteration):

```python
	while (i) < (n) :
		(_t_float)[_stack_ptr_float] = _call_t_1_2yW4Ac
		...
		(_t_float)[_stack_ptr_float] = x
		_stack_ptr_float = (_stack_ptr_float) + ((int)(1))
		x = (x) + ((z) * ((float)(0.1)))
		(_t_int)[_stack_ptr_int] = i
		...
```

After (only the segment's inputs pushed, then one segment runs):

```python
	while (i) < (n) :
		(_t_int)[_stack_ptr_int] = i
		_stack_ptr_int = (_stack_ptr_int) + ((int)(1))
		(_t_float)[_stack_ptr_float] = x
		_stack_ptr_float = (_stack_ptr_float) + ((int)(1))
		_checkpoint_f_0(i,x,n,i,x)
		_loop_var_0 = (_loop_var_0) + ((int)(1))
```

## Privatizing helper calls in parallel code

When a `@simd` function calls a helper, the helper's reverse adds into the shared adjoint without an atomic, so threads race. Privatization gives each thread a local temporary for the call and adds it into the shared adjoint with one atomic.

[extras/loma_code/race_scalar.py](../extras/loma_code/race_scalar.py):

```python
def square(t : In[float]) -> float:
    return t * t

@simd
def square_all(x : In[float], z : Out[Array[float]]):
    i : int = thread_id()
    z[i] = square(x)

rev_square_all = rev_diff(square_all)
```

`test_privatize_race_slang` (100000 threads, expected `dx = 300000`):

```python
assert abs(results[True] - expected) < 1e-4 * expected
```

Generated Slang `rev_square_all`:

```diff
 	_d_call_t_1_2yW4Ac_Y1t9Ew = (float)(0.0);
-	_d_rev_square(x,_dx_q9GFz6[0],_adj_0);
+	_ptmp_0 = (float)(0.0);
+	_d_rev_square(x,_ptmp_0,_adj_0);
+	InterlockedAdd<float>(_dx_q9GFz6[0], _ptmp_0);
 }
```

## Slang `inout` patch

The stock Slang backend can't compile non-`@simd` helpers with scalar `Out` parameters, which every reverse-mode helper has. [extensions/backends.py](../extensions/backends.py) emits them as `inout`. `test_slang_patch_compiles` compiles five programs with the patch: a HW3 kernel, a helper with an `Out` argument, the reverse of a helper call, and a kernel loop with and without checkpointing.
